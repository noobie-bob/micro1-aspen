ProjHub MCP is a cross-tool visibility and unsafe-input task, not a single-tool bug hunt.
Ordinary callers can cross team boundaries through task/project tools, diagnostic tools,
legacy tools, search, prompt construction, module loading, outbound fetches, shell-like
ping targets, and budget-expression evaluation.

The Go substrate mirrors the successful Go calibration style: seeded state, explicit
actors/tokens, sentinel markers, central authorization helpers, a generic tool dispatcher,
and tool outputs that are observable as JSON. Test-authoring is the right shape because
security properties are visible at the tool boundary.

The rubric decomposition follows prior MCP success patterns: multi-caller diagnostic
content checks, command/code injection with positive controls, SSRF non-fetch proof,
module-loading reject-then-safe-control, prompt-boundary assertions, cross-team search
isolation, deletion propagation, same-team lifecycle regression, repeatability, and
body-level test quality.
