A teammate said the ProjHub MCP server feels too permissive when ordinary users call tools. They were able to move across team boundaries that should have stayed separate, and some tool responses looked richer than the same workflow should expose. They also noticed that utility tools such as ping, budget calculation, formatter loading, asset fetching, summarization, diagnostics, and legacy dump do not always behave like normal project/task tools.

We need a Go test suite that pins down the bad behavior without prescribing a particular fix. Write Go tests only. Do not modify server code. Put your tests under `tests/exfiltration/`.

A separate engineer will use your tests to validate their fix, so the suite needs to catch real boundary leaks, content leaks, unsafe tool-input handling, diagnostic exposure, and regression risks while still preserving legitimate same-team, administrative, and safe utility-tool behavior. Submit only your test files as a unified diff via `submit_answer` from `/repo`.
