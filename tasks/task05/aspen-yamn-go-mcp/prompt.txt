A teammate said the ProjHub MCP server feels too permissive when ordinary users call tools. They were able to move across team boundaries that should have stayed separate, and some tool responses looked richer than expected. They also noticed utility tools such as ping, budget calculation, formatter loading, asset fetching, diagnostics, and legacy dump behave differently from normal project/task tools.

Write simple Go unit tests only. Do not modify server code. Put your tests under `tests/exfiltration/`.

Prefer direct unit tests using `NewServer()` and `CallTool(...)`; you do not need to start an HTTP server unless you want to. For content checks, marshal returned tool results or errors to JSON and assert on that serialized string. The suite should catch boundary leaks, content leaks, unsafe tool-input handling, and diagnostic exposure while preserving legitimate same-team, administrative, and safe utility-tool behavior. Submit only your test files as a unified diff via `submit_answer` from `/repo`.
