A teammate said the ProjHub MCP service feels too permissive when they use it as an ordinary user. They were able to move across team and project boundaries that should have stayed separate, and some responses looked richer than the same workflow should expose. They also suspected that some helper and operational paths behave differently from the main project/task surface.

We need a test suite that pins down the bad behavior without prescribing a particular fix. Write Go tests only. Do not modify server code. Put your tests under `tests/exfiltration/`.

A separate engineer will use your tests to validate their fix, so the suite needs to catch real boundary leaks, response-shaping mistakes, unsafe request-handling paths, internal-data exposure, and operational-surface exposure while still preserving legitimate same-team, administrative, and role-appropriate behavior. Submit only your test files as a unified diff via `submit_answer` from `/repo`.
